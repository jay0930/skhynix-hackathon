# 질문·확인 목록: {{과제명}}

실제 과제 작업 공간에서 유지합니다. 문제 정의·구현 중 중요한 미확인 사항을 기록하고, 다음에 확인할 질문부터 대화합니다. 모든 생각이나 일상적인 기술 선택을 승인 항목으로 만들지는 않습니다.

## 분류와 처리 원칙

| 종류 | 확인할 대상 | 질문의 목적 | 주로 생기는 시점 |
|---|---|---|---|
| 종류 1: Problem Context(업무 맥락) | 문제 담당자 Bot | 실제 업무·용어·데이터 의미·제약·평가 기준 등 과제 맥락의 사실 확인 | Jay와 문제를 정의할 때. 구현 중 발견해도 같은 대상으로 분류 |
| 종류 2: Builder 확인 | Jay | 구현 중 불확실한 범위·우선순위·동작·트레이드오프에 대한 선택 확인 | 실제 제작 과정 |

- 먼저 과제 안내·자료·코드·기존 답변을 확인합니다. 이미 답이 있으면 출처와 함께 반영하고 같은 질문을 반복하지 않습니다.
- 자료로 확인 가능한 기술 사실은 AI가 조사하고, 위임된 일상적인 기술 결정은 AI가 판단합니다. Jay에게 기술 선택을 떠넘기지 않습니다.
- Bot에는 사실을, Jay에게는 선택을 묻습니다. 사실 확인과 선택이 섞였으면 연결된 두 질문으로 나누고 사실부터 확인합니다.
- Bot 질문은 AI가 문안으로 정리하고 Jay가 허용된 플랫폼 메신저에서 직접 전달합니다. AI가 전송·응답을 수행했다고 가정하지 않습니다.
- 문서에는 여러 질문을 기록할 수 있지만 대화에서는 가장 중요한 미해결 질문 하나부터 확인합니다.
- 답변이 없으면 승인·기본값 선택으로 간주하지 않습니다. 영향받는 작업만 멈추고 독립적으로 가능한 작업을 진행합니다.
- 답변 확인 후 관련 명세·판단·작업·검증·이해 노트에 실제 반영해야 ‘반영완료’입니다. 답변과 구현·검증 완료는 다릅니다.
